# C++ · Урок 13. Динамическая память (new / delete)

## Цели урока
- Выделять и освобождать память вручную
- Знать про утечки и умные указатели

## Стек и куча
- **Стек** — локальные переменные, освобождаются автоматически при выходе из блока.
- **Куча** (heap) — память, которой вы управляете сами.

## new и delete
```cpp
int* p = new int(42);       // выделили одно int в куче
std::cout << *p << "\n";
delete p;                   // освободили
p = nullptr;

int* arr = new int[5];      // массив в куче
for (int i = 0; i < 5; i++) arr[i] = i * i;
delete[] arr;               // для массивов — delete[]
arr = nullptr;
```
Каждому `new` должен соответствовать `delete`, каждому `new[]` — `delete[]`.

## Динамический размер
```cpp
int n;
std::cin >> n;
double* data = new double[n];
// ... работа
delete[] data;
```
На практике вместо этого используйте `std::vector<double>(n)`.

## Типичные проблемы
| Проблема | Пример |
|---|---|
| Утечка памяти | `new` без `delete` |
| Двойное освобождение | `delete p; delete p;` |
| Висячий указатель | использование `p` после `delete` |
| Неверный вид | `new[]` + `delete` |

## Умные указатели (C++11)
Освобождают память сами:
```cpp
#include <memory>

auto p = std::make_unique<int>(42);       // единственный владелец
std::cout << *p << "\n";

auto s1 = std::make_shared<std::string>("hi");   // общий владелец, счётчик ссылок
auto s2 = s1;
```
Правило: **в современном C++ не используйте голые `new` и `delete`** без необходимости — берите контейнеры и умные указатели (идиома RAII).

## Типичные ошибки
- Забыли `delete` (утечка)
- Использовали указатель после `delete`
- Выход из функции по исключению до `delete`

3. Создайте `unique_ptr` на структуру и выведите её поля.
