# SQL · Урок 19. Представления (VIEW)

## Цели урока
- Создавать представления
- Использовать VIEW как виртуальные таблицы
- Понимать ограничения обновляемых VIEW

## Теория

**VIEW** — сохранённый запрос, который выглядит как таблица.

```sql
CREATE VIEW students_dushanbe AS
SELECT id, name, age
FROM students
WHERE city = 'Душанбе';

SELECT * FROM students_dushanbe;
```

**С JOIN**
```sql
CREATE VIEW book_authors AS
SELECT b.id, b.title, a.name AS author
FROM books b
JOIN authors a ON b.author_id = a.id;
```

**Удаление / замена**
```sql
DROP VIEW students_dushanbe;
-- SQLite 3.24+: CREATE VIEW ... AS ...  (пересоздать)
```

**Зачем**
- Упростить сложные запросы
- Скрыть лишние столбцы
- Единая «версия правды» для отчётов
- Права доступа (в полноценных СУБД)

**Ограничения**
- Не все VIEW можно UPDATE/INSERT (зависит от СУБД и сложности)
- VIEW не хранит данные — только определение запроса
- Изменение базовых таблиц сразу видно через VIEW

## Типичные ошибки
- Ожидание, что VIEW ускоряет запрос сама по себе
- Слишком сложные вложенные VIEW
- Забыли DROP перед пересозданием

## Практика
1. Создайте VIEW «студенты старше 20».
2. Создайте VIEW с книгами и именами авторов.
3. Выберите данные из VIEW с дополнительным WHERE.

## Проверь себя
1. Хранит ли VIEW данные?
2. Можно ли делать JOIN в определении VIEW?
3. Чем VIEW отличается от обычной таблицы?
