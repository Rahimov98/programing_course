# Веб · Урок 22. HTTP и DevTools

## Цели урока
- Понять основы HTTP-запросов и ответов
- Пользоваться вкладками Network, Elements, Console
- Диагностировать типичные проблемы

## Теория

**HTTP в двух словах**
- Запрос: метод (GET, POST…), URL, заголовки, иногда тело
- Ответ: статус (200, 404, 500…), заголовки, тело (HTML, JSON…)

**Частые статусы**
| Код | Значение |
|-----|----------|
| 200 | OK |
| 301/302 | Редирект |
| 404 | Не найдено |
| 500 | Ошибка сервера |

**DevTools → Network**
- Список всех запросов
- Статус, размер, время
- Заголовки Request/Response
- Preview / Response тела

Фильтры: Img, CSS, JS, Fetch/XHR.

**Elements**
- Дерево DOM
- Вычисленный CSS (Computed)
- Изменения «на лету» (не сохраняются)

**Console**
```js
console.log("отладка");
console.error("ошибка");
```
Ошибки JS и сетевые сообщения появляются здесь.

**Application**
- Local Storage, Session Storage, Cookies
- Cache

**Типичный сценарий отладки**
1. Страница «без стилей» → Network: CSS 404? неверный путь?
2. Картинка не грузится → путь, CORS, размер
3. Кнопка не работает → Console: ошибка JS?

## Типичные ошибки
- Смотрят только Elements, игнорируют Network и Console
- Кэш мешает видеть обновления → Disable cache при открытых DevTools
- Путают 404 и ошибку в своём коде

## Практика
1. Откройте свой сайт с DevTools → Network: сколько запросов, есть ли 404?
2. В Elements измените текст и цвет, затем обновите страницу.
3. Вызовите ошибку в JS и найдите её в Console.

## Проверь себя
1. Что означает статус 404?
2. Зачем вкладка Network?
3. Где смотреть ошибки JavaScript?
