# Веб · Урок 23. Публикация и хостинг

## Цели урока
- Выложить сайт в интернет
- Сравнить варианты хостинга
- Подключить свой домен (обзорно)

## Теория

**Варианты для статичного сайта**
| Сервис | Плюсы | Минусы |
|--------|-------|--------|
| GitHub Pages | Бесплатно, просто с Git | Только статика, лимиты |
| Netlify | Drag&drop, формы, CI | Лимиты на бесплатном плане |
| Vercel | Удобно с Git, превью | Ориентация на фреймворки |
| Cloudflare Pages | Быстро, щедрый free | Нужен аккаунт Cloudflare |

**GitHub Pages** — уже разбирали (урок 17).

**Netlify (кратко)**
1. Зарегистрироваться
2. «Add new site» → Deploy manually или подключить репозиторий
3. Drag&drop папки с index.html
4. Получаете URL вида `random-name.netlify.app`

**Свой домен**
1. Купить домен (Namecheap, REG.RU, Cloudflare Registrar…)
2. В настройках хостинга указать домен
3. Прописать DNS-записи (A / CNAME), которые даёт хостинг
4. Подождать распространения DNS (минуты–часы)

**HTTPS**
Современные хостинги выдают сертификат Let's Encrypt бесплатно. Всегда включайте HTTPS.

**Чек-лист перед публикацией**
- [ ] index.html в корне
- [ ] Относительные пути к CSS/JS/картинкам
- [ ] title и description
- [ ] Нет «localhost» и тестовых ссылок
- [ ] Проверка на телефоне
- [ ] Lighthouse без критических ошибок

## Типичные ошибки
- Абсолютные пути `/Users/...` или `C:\...`
- Забыли, что регистр имён файлов на Linux важен
- Кеш DNS/браузера — «сайт не обновился»

## Практика
1. Опубликуйте учебный сайт на GitHub Pages или Netlify.
2. Откройте с телефона по выданной ссылке.
3. (Опционально) Подключите свой домен, если есть.

## Проверь себя
1. Чем статический хостинг отличается от VPS?
2. Зачем HTTPS?
3. Что проверить перед деплоем?
