# SQL · Урок 20. Транзакции

## Цели урока
- Понять ACID и зачем нужны транзакции
- Использовать BEGIN, COMMIT, ROLLBACK
- Обеспечивать целостность при нескольких операциях

## Теория

**Транзакция** — группа операций, которая выполняется целиком или не выполняется совсем.

**ACID**
- **Atomicity** — всё или ничего
- **Consistency** — БД остаётся в согласованном состоянии
- **Isolation** — транзакции не мешают друг другу
- **Durability** — после COMMIT данные сохранены

```sql
BEGIN TRANSACTION;   -- или просто BEGIN;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;              -- зафиксировать
-- или
ROLLBACK;            -- отменить всё
```

**Пример перевода денег**
```sql
BEGIN;
UPDATE accounts SET balance = balance - 500 WHERE id = 1 AND balance >= 500;
-- проверить изменения
UPDATE accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;
```

**Автокоммит**
По умолчанию каждый запрос — отдельная транзакция. Явный BEGIN объединяет несколько.

**SAVEPOINT** (вложенные точки)
```sql
BEGIN;
SAVEPOINT sp1;
-- операции
ROLLBACK TO sp1;   -- откат до точки
COMMIT;
```

## Типичные ошибки
- Забыли COMMIT → изменения «висят»
- Долгие транзакции блокируют других
- Обработка ошибок без ROLLBACK

## Практика
1. Начните транзакцию, обновите две строки, сделайте COMMIT.
2. Сделайте то же, но ROLLBACK — убедитесь, что данные не изменились.
3. Смоделируйте перевод: списание и зачисление в одной транзакции.
